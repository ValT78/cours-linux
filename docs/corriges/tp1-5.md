# Corrigé du TP 1.5 — Reprendre le contrôle du terminal

Reprends le [sujet](../eleves/tp1-5-maitriser-terminal.md) et ton carnet. Les chemins partent de `station-nadir` jusqu’au niveau 7, puis de `atelier-permissions`. Les messages d’erreur et les noms de compte dépendent de ta session.

## Niveaux 0 et 1 — Retrouver tes repères

**N01.** `/` désigne la racine, `~` ton dossier personnel après développement par Bash, `.` ton dossier courant et `..` son parent. `ls` liste le dossier courant. `ls /` liste la racine. `mkdir` crée un dossier. `touch` crée un fichier vide s’il manque et actualise ses dates s’il existe.

**N02.** Depuis la station, `ls` affiche par exemple `navigation` et `transmissions`. `ls /` affiche des noms comme `etc` et `tmp`. Le chemin donné en argument choisit le dossier à lister.

**N03.** `cd /~` cherche un dossier nommé `~` sous la racine. Bash développe le tilde non protégé au début du mot. Ici, le mot commence par `/`. Le message signale généralement « Aucun fichier ou dossier de ce type ». Pour revenir chez toi, tape `cd ~`.

**N04.** Depuis la station, `cd navigation/secteur-beta` puis `cat carte.txt` montre la carte du secteur BETA. De là, `cd ../..` remonte deux fois et revient à la station. Ce chemin relatif dépend de ton point de départ. Depuis `/tmp`, utilise le chemin complet donné par `pwd` dans la station. Pour Alice, ce serait `cd /home/alice/base-exploration/tp1-5/station-nadir`.

## Niveau 2 — Réutiliser des commandes

**N05.** Par exemple, la flèche `↑` rappelle le `ls` des trois secteurs. Tu peux alors changer `-la` en `-ld`. Avec `Ctrl+R`, tape `00-LIRE` pour retrouver une commande qui consultait le fichier de départ. `Ctrl+C` permet d’annuler la recherche sans lancer la commande.

**N06.** `ls -a navigation` révèle le dossier `.indices`. Le point initial explique pourquoi `ls navigation` le masque. `cat navigation/.indices/fragment-station.txt` donne le fragment **NADIR**.

## Niveau 3 — Manipuler des fichiers

**N07.** `mkdir travail/enquete` crée un dossier. `touch travail/enquete/observations.txt` crée ici un fichier vide. Le premier caractère de `ls -ld travail/enquete` est `d`. Pour le fichier, `ls -l travail/enquete/observations.txt` commence par `-`.

**N08.** `cat travail/enquete/test.txt` affiche seulement `nouvelle hypothese`. La deuxième redirection `>` remplace le contenu écrit par la première. Avec `>>` sur la deuxième commande, les deux lignes resteraient.

**N09.** Bash refuse `echo "test" > travail/enquete` avec un message du type « est un dossier ». La redirection attend un fichier. Donne-lui un nom dans ce dossier.

```bash
echo "test" > travail/enquete/test-redirection.txt
```

Pour l’exercice de copie et de suppression, voici une suite possible.

```bash
cp travail/enquete/observations.txt travail/enquete/observations-secours.txt
touch travail/enquete/.progression
mkdir travail/enquete/indices-valides
ls -la travail/enquete
rm travail/enquete/observations-secours.txt
ls -la travail/enquete
```

## Niveaux 4 à 6 — Observer, lire et chercher

**N10.** Le tableau donne les quatre solutions. Dans tes notes, le sujet te demande d’en expliquer deux.

| Recherche | Commande et résultat |
|---|---|
| Entrées cachées de `navigation` | `ls -a navigation` inclut les noms qui commencent par un point. Le dossier caché est `.indices`. |
| Plus gros journal | `ls -lS transmissions` affiche les tailles en octets et trie de la plus grande à la plus petite. Le premier journal est `radio-2026-09-16.log`. |
| Droits de `travail` | `ls -ld travail` décrit le dossier lui-même grâce à `-d`. |
| Contenu de l’inventaire | `ls -R inventaire` descend dans les sous-dossiers. Il montre `materiel.csv` et `anciens/inventaire-2024.txt`. |

**N11.** `less` permet de lire et de chercher dans 700 lignes écran par écran. `nano` ouvre le texte dans un éditeur et permet d’enregistrer tes changements.

**N12.** `-n 5` demande cinq lignes. `head` prend les cinq premières et révèle **A7** le 15 septembre. `tail` prend les cinq dernières et révèle **42** le 16 septembre. Dans `head 5 ...`, la commande cherche un fichier nommé `5`. Écris `head -n 5 transmissions/radio-2026-09-15.log`.

**N13.** `grep -n 'ANOMALIE-ROUGE' transmissions/radio-2026-09-14.log` affiche le secteur **DELTA** à la ligne **318**. `-n` affiche le numéro de ligne. `grep` sélectionne les lignes qui contiennent le motif. `cat` afficherait tout le journal.

**N14.** Avec les arguments inversés, `grep` prend `transmissions/radio-2026-09-14.log` pour le motif et essaie d’ouvrir `ANOMALIE-ROUGE` comme fichier. Le message indique que ce fichier est introuvable. Remets le motif devant le fichier, comme en N13.

Pour les recherches du 15 septembre, utilise les deux commandes ci-dessous. Dans le manuel, ouvre `less documentation/manuel-station.txt` et cherche `/PROTOCOLE-ORION`. Le fragment affiché est **VEGA**.

```bash
grep -i 'archive' transmissions/radio-2026-09-15.log
grep -n 'AVERTISSEMENT' transmissions/radio-2026-09-15.log
```

## Niveaux 7 et 8 — Éditer et identifier

**N15.** Par exemple, ajoute une ligne `Code` à ton rapport, puis déplace-la au début. Copie son texte avec `Ctrl+Shift+C`, retire la ligne avec `Ctrl+K` et colle le texte en haut avec `Ctrl+Shift+V`. Enregistre avec `Ctrl+S` et quitte avec `Ctrl+X`. Relis le fichier avec `cat` ou `less` pour vérifier le texte enregistré et l’ordre des lignes.

**N16.** `whoami` donne le nom de ton utilisateur. `id -gn` donne le nom de ton groupe principal. `id` donne aussi l’UID, le numéro que Linux utilise pour identifier ton compte, et les informations sur tes groupes.

## Niveaux 9 à 11 — Comprendre les permissions

**N17.** Après `chmod u-w documents/rapport-public.txt`, la lecture fonctionne et l’ajout avec `>>` est refusé. Le propriétaire conserve `r` et perd `w`. Restaure ce droit avec `chmod u+w documents/rapport-public.txt`.

**N18.** En mode `u=,g=r,o=`, `cat laboratoire/groupe-seul.txt` est refusé depuis le compte propriétaire. Linux choisit les droits de la catégorie propriétaire. Ici, cette catégorie est vide.

**N19.** `chmod u=rw,g=r,o= equipe/partage-equipe.txt` fixe les droits du propriétaire à `rw`, ceux du groupe à `r` et ceux des autres à aucun droit. En chiffres, cela donne `640`, avec `4 + 2` pour le propriétaire, `4` pour le groupe et `0` pour les autres.

**N20.** Par exemple, `750` sur `scripts/diagnostic.sh` donne `rwx r-x ---`. Le calcul est `4 + 2 + 1`, puis `4 + 1`, puis `0`. La forme symbolique est `chmod u=rwx,g=rx,o= scripts/diagnostic.sh`. Le mode `758` est refusé, car chaque chiffre de droits va de `0` à `7`.

Voici les réglages finaux de l’atelier.

```bash
chmod 644 documents/rapport-public.txt
chmod 640 equipe/partage-equipe.txt
chmod 750 scripts/diagnostic.sh
chmod 600 coffre/secret.txt
ls -l documents/rapport-public.txt equipe/partage-equipe.txt scripts/diagnostic.sh coffre/secret.txt
./scripts/diagnostic.sh
```

**N21.** Après avoir retiré `w` sur `depot`, la création de `nouveau.txt` et la suppression de `temoin.txt` échouent. Elles changent la liste des noms du dossier. `cat` peut lire le témoin si le fichier reste lisible et le dossier traversable. Sur un fichier, `w` concerne son contenu. L’expérience dans `depot-2` donne les mêmes résultats avec un témoin lisible. Restaure `w` avec `chmod u+w` sur chaque dossier testé.

Trois réflexes possibles quand une commande échoue.

1. Lis le message et repère le nom qu’il cite.
2. Vérifie ton emplacement avec `pwd` et les noms disponibles avec `ls`.
3. Vérifie l’ordre des arguments dans l’aide, puis reteste.
