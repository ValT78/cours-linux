# Corrigé du TP 2.5 — Construire ses premiers scripts Bash

Reprends le [sujet](../eleves/tp2-5-premiers-scripts.md) et ton carnet. Enregistre chaque script dans `atelier-aurore/scripts`. Pour l’essayer, place-toi dans le dossier indiqué et lance-le avec `bash ../scripts/nom-du-script.sh`. Remplace `nom-du-script.sh` par le nom de l’exercice.

## Niveau 0 — Lire et lancer une recette

**N01.** `cat` affiche les lignes du script. `bash` les exécute. Pour lancer directement `./scripts/bonjour.sh`, donne le droit `x` au propriétaire avec `chmod u+x scripts/bonjour.sh`. Depuis `essais`, `pwd` affiche le chemin de `essais` car c’est ton dossier de lancement.

**N02.** `message.txt` contient seulement `nouveau départ`. Le dernier `>` remplace les deux lignes précédentes. `wc -l < message.txt` reçoit le contenu du fichier sur son entrée standard et affiche seulement `1`. Le message sur `absent.txt` va dans `erreurs.txt` grâce à `2>`.

## Niveau 1 — `infos.sh`

**N03.** `echo '$HOME'` affiche littéralement `$HOME`. `echo "$HOME"` affiche la valeur de la variable, par exemple `/home/alice`.

**Dans `scripts/infos.sh`**, écris cette ligne de sortie.

```bash
#!/usr/bin/env bash
echo "\$HOME=$HOME, \$PWD=$PWD, \$(date)=$(date '+%H :%M.%S')"
```

**N04.** `$HOME` donne le dossier personnel. `$PWD` donne le dossier courant. `$(date '+%H :%M.%S')` insère l’heure au format demandé. Chaque `\$` affiche un dollar littéral dans une étiquette. Lance le script depuis `essais`, puis depuis `projet`. Le chemin après `$PWD=` change. L’heure est recalculée à chaque lancement.

## Niveau 2 — `projet.sh`

**N05.** Le quatrième `echo` produit six chemins, soit deux secteurs avec trois numéros chacun. Les accolades construisent des noms même quand les fichiers n’existent pas. L’étoile cherche des noms existants.

**Dans `scripts/projet.sh`**, garde deux commandes de travail.

```bash
#!/usr/bin/env bash
mkdir -p projet_{doc,src,test}
touch projet_{doc,src,test}/fic{01..10}.txt
```

**N06.** Lance depuis `projet`. `mkdir -p` prépare les dossiers avant `touch`, qui a besoin de ces dossiers pour créer les fichiers. `ls -R` doit montrer `fic01.txt` à `fic10.txt` dans chacun des trois dossiers, soit **30 fichiers**.

## Niveau 3 — `comptes.sh`

**N07.** Le champ 1 donne le nom du compte et le champ 6 son dossier personnel. `cut -d':' -f1,7` garde le nom et le shell de connexion. Les deux restent séparés par `:`, comme dans `alice:/bin/bash`.

**Dans `scripts/comptes.sh`**, relie les trois outils.

```bash
#!/usr/bin/env bash
cut -d':' -f1 /etc/passwd | sort | paste -sd ' ' -
```

**N08.** `cut` extrait les noms et `sort` trie les lignes. Trie tant que chaque nom occupe une ligne. Une fois les noms réunis, `sort` ne peut plus les classer séparément. `paste -s` réunit les lignes en une seule. `-d ' '` choisit l’espace entre les noms et le dernier `-` lit le résultat du tube. La ligne se termine par un retour à la ligne. Depuis `essais`, remplace temporairement `/etc/passwd` par `comptes-exemple.txt` pour obtenir `alice robot sam zoe`.

## Niveau 4 — `etc.sh`

**Dans `scripts/etc.sh`**, calcule le nom du rapport une fois.

```bash
#!/usr/bin/env bash
rapport="etc.$(date +%y.%m.%d)"
ls -1 /etc > "$rapport"
wc -l < "$rapport"
```

**N09.** La variable `rapport` permet d’écrire et de relire le même fichier. Par exemple, le 7 octobre 2026, son nom est `etc.26.10.07`. `ls -1` écrit une entrée visible par ligne. `wc -l` affiche le nombre de lignes, qui dépend de ta machine. Relance le script le même jour depuis `essais`. `>` reconstruit le fichier à chaque passage. `>>` ajouterait une deuxième liste.

## Niveau 5 — `recents.sh`

**N10.** Après avoir préparé les dates du sujet, les trois fichiers les plus récents sont `zeta.txt`, `milieu.txt` et `beta.txt`, du plus récent au plus ancien. Par ordre alphabétique, ils deviennent `beta.txt`, `milieu.txt`, `zeta.txt`.

**Dans `scripts/recents.sh`**, sélectionne les noms avant de les ranger.

```bash
#!/usr/bin/env bash
ls -1t | head -n 3 | sort
```

**N11.** Lance depuis `recents`. Le premier essai donne les trois noms dans l’ordre alphabétique de N10, un par ligne. Après `touch ancien.txt`, tu obtiens `ancien.txt`, `milieu.txt` et `zeta.txt`. `ls -1t` classe d’abord par date et `head` garde les trois premiers. Un tri alphabétique avant `head` ferait la sélection sur les noms.

## Niveau 6 — `csv.sh`

**N12.** `ligne.txt` contient `3` et `colonne.txt` contient `2`. En comptant l’en-tête comme première ligne, la case demandée contient `SUD`.

**Dans `scripts/csv.sh`**, lis les deux numéros au lancement.

```bash
#!/usr/bin/env bash
ligne=$(cat ligne.txt)
colonne=$(cat colonne.txt)
head -n "$ligne" fichier.csv | tail -n 1 | cut -d';' -f"$colonne"
```

**N13.** `head` garde les premières lignes jusqu’au numéro demandé. `tail -n 1` garde seulement la dernière de ce groupe. `cut` extrait la colonne. Depuis `csv`, teste les trois coordonnées. Le script lit les fichiers à chaque exécution pour suivre les changements.

| Ligne | Colonne | Valeur |
|---:|---:|---|
| 3 | 2 | `SUD` |
| 4 | 3 | `OK` |
| 1 | 2 | `zone` |

Restaure ensuite `3` dans `ligne.txt` et `2` dans `colonne.txt`.

## Niveau 7 — `shells.sh`

**N14.** Le tri du test donne `sam EST`, `zoe EST`, puis `alice NORD`. `EST` vient avant `NORD`. Dans le groupe `EST`, `sam` vient avant `zoe`.

**Dans `scripts/shells.sh`**, choisis deux clés de tri.

```bash
#!/usr/bin/env bash
cut -d':' -f1,7 /etc/passwd | tr ':' ' ' | sort -k2,2 -k1,1
```

**N15.** `cut` garde le nom et le shell. `tr` remplace le séparateur par un espace. `sort -k2,2 -k1,1` trie par le deuxième champ, puis par le premier en cas d’égalité. Un simple `sort` commencerait par le début de la ligne, donc par le nom. Avec `comptes-exemple.txt`, `alice /bin/bash` et `zoe /bin/bash` se suivent dans cet ordre.

## Niveau 8 — `production.sh`

**N16.** `wc -l < "$fichier"` fournit le nombre seul. Tu peux alors placer le nom avant ce nombre avec `printf`. Dans la clé de tri, `n` compare des nombres et `r` inverse l’ordre. Avec `nullglob`, un motif sans correspondance disparaît de la liste.

**Dans `scripts/production.sh`**, envoie au tri toutes les lignes de la boucle.

```bash
#!/usr/bin/env bash
shopt -s nullglob
for fichier in *.c *.h
do
    nombre=$(wc -l < "$fichier")
    printf '%s %s\n' "$fichier" "$nombre"
done | sort -k2,2nr
```

**N17.** `fichier` reçoit un nom différent à chaque passage. Le tube après `done` transmet au tri toutes les lignes `nom nombre`. Depuis `production`, tu dois obtenir le résultat suivant. Dans un dossier vide, la boucle ne produit aucune ligne et le tri reste silencieux.

```text
radio.c 7
main.c 5
radio.h 2
```

## Niveau 9 — `nettoyage.sh`

**N18.** Dans `essais`, la sélection du niveau 9.2 retient `accepte.txt` et `refuse.txt` après la préparation des dates. `-maxdepth 1` empêche `find` de descendre dans les sous-dossiers. `-mtime +3` demande plus de trois journées **complètes**, donc au moins quatre jours. Ici, `-mmin +4320` sélectionne à partir de 4 321 minutes complètes.

**Dans `scripts/nettoyage.sh`**, sélectionne les fichiers, demande confirmation et consigne chaque suppression réussie.

```bash
#!/usr/bin/env bash
find . -maxdepth 1 -type f -mmin +4320 ! -name 'nettoyage.log' \
    -ok rm -- {} \; -printf '%f\n' >> nettoyage.log
```

La barre oblique inverse en fin de première ligne prolonge la commande. `-ok` demande confirmation avant d’appeler `rm` sur le chemin `{}`. `-printf` affiche le nom seul après un accord et une suppression réussie. Les questions restent visibles dans le terminal.

**N19.** Après avoir préparé les dates, lance le script seulement depuis `nettoyage`. Accepte `a-retirer.txt` et refuse `a-garder.txt`, quel que soit leur ordre. `recent.txt` est trop récent. `-maxdepth 1` protège `sous-dossier/ancien-profond.txt` et le dossier `essais` reste en place. Le journal contient une seule ligne `a-retirer.txt` au premier essai. Si tu refuses le candidat restant au second passage, le journal garde cette même ligne. Journaliser avant l’action compterait aussi les refus et les échecs.

## Niveau 10 — `quibosse.sh`

**N20.** Un compte désigne une identité connue de la machine. Une session correspond à une connexion ouverte et enregistrée. Un même compte peut avoir plusieurs sessions. La date occupe le champ 3 et l’heure le champ 4.

**Dans `scripts/quibosse.sh`**, trie les sessions avant de les afficher et de les enregistrer.

```bash
#!/usr/bin/env bash
LC_ALL=C who | sort -k3,3 -k4,4 | tee -a quibosse.log
```

**N21.** Depuis `connexions`, essaie d’abord `sort -k3,3 -k4,4 connexions-exemple.txt | tee -a quibosse.log`. À chaque passage, le résultat est le suivant.

```text
sam pts/3 2026-09-21 23:50 (192.0.2.13)
alice pts/0 2026-09-22 08:05 (192.0.2.10)
alice pts/1 2026-09-22 11:20 (192.0.2.10)
zoe pts/2 2026-09-22 14:10 (192.0.2.12)
```

`tee -a` affiche le relevé et l’ajoute à la fin du journal. Deux passages à partir d’un journal vide donnent deux blocs identiques, soit huit lignes. Lance ensuite le script avec `who`. Le relevé dépend des sessions enregistrées sur ta machine. Si `who` ne donne aucune ligne, l’écran reste vide et le journal ne gagne aucune ligne.
